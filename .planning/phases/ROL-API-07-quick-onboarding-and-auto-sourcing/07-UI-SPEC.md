# Phase 07 - UI Design Contract

> Visual and interaction contract for Quick Onboarding and Auto Sourcing. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - use existing bespoke React/CSS system |
| Preset | not applicable |
| Component library | local components only: `Button`, `Card`, `InlineAlert`, form primitives, chips, page scaffold |
| Icon library | local inline SVG icons from `apps/web/src/components/icons.jsx` |
| Font | Geist Sans for UI, Geist Mono for code/count metadata |

Source: `apps/web/src/styles/tokens.css`, `apps/web/src/styles/app.css`, `apps/web/src/components/*`, and Phase 7 RESEARCH.md. No `components.json`, Tailwind, Radix, or shadcn registry is present or needed for this phase.

### Component Inventory

| Surface | Required Component Pattern |
|---------|----------------------------|
| Resume DOCX intake | Existing `ResumeStep` `Card` + `.dropzone` + `InlineAlert` + paste fallback |
| Search readiness | Existing setup readiness grid/card pattern, with Search/Gate/Apply/Deep ingest kept separate |
| First-search task | Compact setup checklist row/card, not a modal and not a persistent nag |
| Cadence selection | Field group with segmented/radio-style choices; one option visually marked recommended |
| Running/completed/failed states | Status chip/badge plus one concise detail line; no left-edge accent strips |
| Jobs rerun | `JobsPage` page-header action using `Button`, gated by DB source setup |

Hard visual rules for this phase:
- Do not add a landing page, hero, marketing panel, or nested cards.
- Do not use chat panels for first search.
- Do not use colored left borders or accent strips on cards.
- Do not introduce new global tokens unless an existing token cannot express the state.

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, tiny status/meta separation |
| sm | 8px | Compact row gaps, chip rows, form control grouping |
| md | 16px | Default card/body vertical gaps and wizard sections |
| lg | 24px | Page/header spacing and dropzone vertical rhythm |
| xl | 32px | Main content padding on desktop |
| 2xl | 48px | Wide layout max padding via existing clamp |
| 3xl | 64px | Reserved for app-shell/page separation only |

Exceptions: Existing component internals in `app.css` may retain current CSS values; new Phase 7 layout spacing must use the scale above. New icon-only controls must be at least 32px square, matching `.icon-btn`; use 44px minimum only for new mobile-only tap targets.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--paper-bg)` / `#faf6ef` | App background and page canvas |
| Secondary (30%) | `var(--paper-surface)` / `#fffaf2`; `var(--paper-band)` / `#f5f0e8` | Cards, checklist rows, neutral chips, dropzone rest state |
| Accent (10%) | `var(--m-secondary)` / `#e8553d` | Primary CTA, active wizard/filter state, focus outline, active dropzone border |
| Destructive | `var(--danger)` / `#ba2f20`; `var(--m-error-container)` / `#ffe0d8` | Error alerts and destructive actions only |

Accent reserved for: `Search jobs now`, `Search jobs`, active cadence choice, active filter/wizard pill, keyboard focus outlines, and drag-active dropzone border. Do not use accent as generic decoration.

Semantic status colors:
- Completed/Ready: `var(--teal)` text on `var(--teal-light)` background.
- Running/Not started/Needs setup: `var(--mustard)` text on `var(--mustard-light)` background.
- Failed/Error: `var(--m-error)` text on `var(--m-error-container)` background.
- Links/actions inside job rows: existing `var(--sky)` only.

Dark mode must inherit from `[data-theme="dark"]` tokens. Do not hardcode light-only status backgrounds in components.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Search jobs now |
| Secondary first-run action | Not now |
| Jobs rerun CTA | Search jobs |
| Empty state heading | No search run yet |
| Empty state body | Complete Search setup, choose a cadence, then start the first deterministic search. |
| Zero-results completed state | Search completed. No matching roles found yet; refine titles or add a source, then search again from Jobs. |
| Error state | First search failed. Review the source setup message, fix the issue, then retry. |
| DOCX fallback error | We could not read usable text from that DOCX. The original file was saved; paste text or upload PDF, TXT, or Markdown. |
| Destructive confirmation | none - Phase 7 adds no destructive user action |

Copy rules:
- Use "search" and "sourcing" for local deterministic runs; do not say "agent", "chat", "skill", or "automation" for the first run.
- When cadence uses a default recommendation, label it `Default recommendation - no local history yet`.
- When cadence is data-backed, label it `Recommended from recent search history`.
- Do not imply a hidden scheduler. Cadence is a preference unless implementation adds a durable start/stop schedule.

## Interaction Contract

### Search-Ready Prompt

- When `search_ready` first becomes true, show a first-search setup task in onboarding.
- Ask the user "Search now?" with the yes path selected by default.
- If the user clicks the normal continue action without explicitly choosing `Not now`, start the first deterministic search.
- If the user chooses `Not now`, keep the task at `Not started` and show `Search jobs now` as the next available action.
- Never start `/api/chat/*`, `/api/discovery/quick-start`, `/api/discovery/next`, `research-boards`, `discover-companies`, `search-jobs`, or `POST /api/skill/run` from this first-search UI.

### Cadence Choice

- Show cadence before or inside the first-search task.
- Required choices: `Daily`, `Every 3 days`, `Weekly`, `Manual only`.
- Default selected option: `Daily` unless local/source history supports another recommendation.
- The selected cadence must be visible after save as a compact line, e.g. `Cadence: Daily`.
- Missing cadence must not block `search_ready`, but the first-run card must ask for it before start.

### First-Search Statuses

| Status | Label | Required UI |
|--------|-------|-------------|
| `not_started` | Not started | Neutral checklist row, `Search jobs now` CTA enabled when search-ready |
| `running` | Running | Disable start buttons, show `Searching deterministic public sources...`, keep deep onboarding links/actions available |
| `completed` | Completed | Show counts for sources attempted and roles found; show `View sourced roles` link when count > 0 |
| `failed` | Failed | Show actionable error text and `Retry search` CTA |

If a run attempts deterministic sources and finds zero roles, show `completed` with zero-results copy. If no deterministic source was attempted, show `failed` with a source-setup action.

### Resume Intake

- Add `.docx` to the upload accept list regardless of AI key state.
- Present DOCX as local deterministic parsing: `DOCX, TXT, and Markdown are parsed locally. PDF and images use your connected AI key.`
- On DOCX extraction success, use the same Review & edit panel as text/PDF paths.
- On empty or garbled DOCX extraction, keep the original file saved, do not mark source resume ready, open the paste fallback, and show the DOCX fallback error above.
- Do not feed DOCX to AI by default.

### Jobs Page Rerun

- Show a `Search jobs` action in the Jobs page header only after DB source setup exists.
- While a scan is running, disable the action and label it `Searching...`.
- If no DB source setup exists, do not show the action as enabled; use a concise hint: `Finish Search setup before running a job search.`
- Manual reruns use the same durable run-status model as onboarding when available.
