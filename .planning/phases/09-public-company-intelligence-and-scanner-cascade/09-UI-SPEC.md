# Phase 09 - UI Design Contract

> Visual and interaction contract for Phase 09: Public Company Intelligence and Scanner Cascade. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope Boundary

This phase adds only compact operational UI for:

1. A default-on public sync-home consent control in the onboarding/default setup path.
2. A local review surface for ambiguous or conflicting public scanner results.
3. Local warning/error states when scrub validation blocks publish or scanner cascade work needs review.

Do not build a marketing page, hero, public dashboard, legacy tracker UX, or a generic scanner console. The app remains `/app` plus SQLite-backed local APIs. Compatibility tracker/export surfaces stay out of product UX.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon/text gaps and tight metadata spacing |
| sm | 8px | Chip gaps, row gaps, compact control grouping |
| md | 16px | Default card body gaps and form section rhythm |
| lg | 24px | Page/card group spacing and onboarding step separation |
| xl | 32px | App content top/bottom padding on desktop |
| 2xl | 48px | Wide layout side padding maximum via existing responsive shell |
| 3xl | 64px | Reserved for page-level breaks only; not expected in this phase |

Exceptions: reuse existing component internals instead of restyling them: `.btn`, `.card`, `.toggle`, badges, and chips inherit their current legacy internal padding/sizing outside this Phase 09 spacing scale. Do not declare, override, or introduce new non-grid padding values in this phase. New wrapper/layout spacing for Phase 09 must use the declared scale above. Standalone icon buttons stay 32px minimum on desktop; touch-heavy mobile actions must preserve at least 44px tap height through row wrapping or button flex sizing.

## Typography

Use exactly these four UI sizes for new Phase 09 copy. Use only regular 400 and semibold 600 for new text; do not add new bold/display treatments.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.5 |
| Label | 12px | 600 | 1.5 |
| Heading | 22px | 600 | 1.2 |
| Metadata | 13px | 400 | 1.5 |

Implementation notes:
- Page titles use the existing `.page-scaffold__title` pattern.
- Card titles should use existing `Card` title styling; do not create larger section headers inside cards.
- Consent body copy must be 14px body text, not a legal-disclaimer wall.
- Scanner review metadata, provenance, freshness, and confidence should render as 12px/13px hints, badges, and chips.

## Color

Use CSS variables, not hardcoded one-off colors. The dark theme must continue to work through existing `[data-theme="dark"]` token overrides.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--paper-bg)` / `#faf6ef` | App background and page canvas |
| Secondary (30%) | `var(--paper-surface)` / `#fffaf2`; `var(--paper-band)` / `#f5f0e8` | Cards, rows, chip backgrounds, URL/provenance bands |
| Accent (10%) | `var(--m-secondary)` / `#e8553d` | Primary CTA, enabled toggle track, active wizard/selected chip state, approve-supported-ATS action only |
| Destructive | `var(--danger)` / `#ba2f20` | Destructive actions only; none are required by this phase |

Accent reserved for: `Save sharing preference`, enabled sync-home toggle, active wizard rail/selected chip states, and a supported-ATS approval action. Do not use accent for every link, every badge, every scanner status, or decorative emphasis. Use existing `badge--warn` for ambiguous/conflict review states, `badge--ok` for scrubbed/ready states, `badge--muted` for inactive or no-review states, and `InlineAlert` error styling for blocked scrub/publish failures.

## Primary Visual Anchor

- Onboarding consent: the enabled sync-home `Toggle` is the primary visual anchor, paired with the `Save sharing preference` CTA inside the consent card. Keep the toggle, label, and saved-state hint visually grouped.
- Scanner review items: the review-reason badge plus the wrapped action row are the primary visual anchor. Place the badge with the required metadata and keep the decision actions immediately adjacent so the reason and available choices scan as one unit.

| Element | Copy |
|---------|------|
| Primary CTA | Save sharing preference |
| Empty state heading | No scanner reviews |
| Empty state body | CareerRat only asks when public board metadata is ambiguous or conflicting. Clean misses are recorded locally and do not interrupt you. |
| Error state | Public sync blocked: private data was detected. Review the local record and retry after scrub validation passes. |
| Destructive confirmation | None. Disabling sharing and suppressing a scanner review are reversible local preferences, not destructive deletes. |

Required consent copy:

| Element | Copy |
|---------|------|
| Consent card title | Help improve public company data |
| Toggle label | Share public company and job-board metadata |
| Consent body | CareerRat can share scrubbed public metadata about companies and careers boards to improve future discovery. Resume, profile, notes, compensation, fit scores, jobs, tracker state, and local files never leave this workspace. |
| On state hint | Sharing is on by default and only reads public metadata records. |
| Off state hint | Sharing is off. Local discovery still works. |

Required scanner review copy:

| State | Copy |
|-------|------|
| Ambiguous provider | Multiple board matches found. Choose the source CareerRat should use locally. |
| Provider changed | The provider appears to have changed since the last scan. Review before updating public metadata. |
| Robots/blocked with prior data | The page is blocked now, but prior public metadata exists. Keep the prior record, refresh later, or suppress this result. |
| Low confidence extraction | CareerRat found public page text but could not confidently identify the careers board. Review before using it. |
| Found nothing useful | No visible prompt. Store freshness/failure metadata locally and continue. |

## Interaction Contract

### Sync-Home Consent

- Place one consent control in the onboarding/default setup flow, preferably as a compact `Card` near source/search setup or the finish/setup readiness area.
- Use the existing `Toggle` component. The initial checked state is `true` unless saved preference says otherwise.
- Do not show more than one sync-home toggle in onboarding. If Settings mirrors the preference later, reuse the same label/body copy and persisted state.
- Saving behavior must be explicit: use `Save sharing preference` or the current step's `Save & continue` action. While saving, disable the control/CTA and use `Saving...`.
- The toggle must not imply that private candidate data, job postings, sourced rows, tracker state, local paths, or fit/comp data can sync.
- The first publish attempt after consent still depends on scrub validation. Consent is not a bypass.

### Scanner Review Surface

- Reuse the existing company proposal visual pattern: `Card` section, `company-row company-row--proposal`, `CompanyAvatar`, compact metadata under the company/domain, and a wrapped `proposal-actions` row for actions.
- Show review UI only for ambiguity/conflict cases named in Phase 09 context: provider changes, multiple plausible boards, blocked scrape with prior data, robots-disallowed paths, or low-confidence extracted metadata/jobs/board metadata.
- Do not interrupt for a clean miss. Record freshness/failure metadata and leave the UI quiet.
- Required row metadata: company/domain, careers URL if known, provider/classification, confidence, freshness, provenance, and reason review is required.
- Required actions:
  - `Use supported ATS` - primary, enabled only when validation resolves a supported ATS.
  - `Keep public metadata` - secondary, for unsupported/custom metadata that should remain cache/review data only.
  - `Refresh scan` - secondary, reruns the cascade for that company/board.
  - `Suppress review` - secondary, hides this review item from normal prompts without deleting canonical private state.
  - `Escalate to agent` - secondary, routes to explicit chat/agent path only when runtime capability allows it.
- Use `InlineAlert` for stale conflict and scrub failure messages. Do not open a modal for ordinary scanner ambiguity.
- When a decision call returns stale/conflict, keep the row visible, show warning copy, refresh the data, and require the user to review the refreshed row before deciding.

### Loading, Empty, and Error States

- Loading labels use existing short copy: `Loading...`, `Finding...`, `Saving...`, `Working...`.
- Empty scanner review state may be omitted entirely in onboarding; if a persistent review panel exists, render the specified empty heading/body.
- Missing SQLite is a product setup error and must use existing no-database `InlineAlert` style. Do not fall back to tracker exports.
- Scrub validation failure is local and blocking. It must show what category failed, without printing private values.
- No-AI or unavailable optional fallback must degrade to local/manual review copy, not chat or full skill runtime.

## Component Inventory

| Need | Component/Pattern |
|------|-------------------|
| Page shell | `PageScaffold` with default width; use `wide` only if a run review list needs more than form-card width |
| Consent control | `Card` + `Field`/plain body copy + `Toggle` + `Button` |
| Review item | `company-row company-row--proposal` + `CompanyAvatar` + status metadata + wrapped action buttons |
| State markers | Existing `badge`, `badge--ok`, `badge--warn`, `badge--muted`, `badge--error` |
| Warnings/errors | `InlineAlert`; warning tone may use existing warning styling if present, otherwise use warning badge plus error alert styling only for hard block |
| Provenance/freshness | `chip-row` and `chip`; long URLs use `board-preview__url` wrapping behavior |
| Success feedback | `Toast` for saved preference or completed decision |

Do not add nested cards, left-edge accent strips, dense tables, hero layouts, gradient backgrounds, or new one-off component systems.
