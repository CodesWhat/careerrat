## Truths

- D-01: Plans 09-01, 09-02, and 09-06 keep public sync scoped to reusable company and job-board/careers intelligence and explicitly forbid individual job postings.
- D-02: Plans 09-02 and 09-03 require public records to carry stable IDs, company/domain, careers URL, provider/custom classification, provenance, freshness, confidence, extraction status, and conflict metadata.
- D-03: Plans 09-01, 09-02, and 09-06 require scrub tests for resume/profile facts, candidate context, comp floors, fit scores, private notes, tracker/application IDs, sourced IDs, local paths, and job-search state.
- D-04: Plan 09-02 creates separate `public_*` tables in the same SQLite DB.
- D-05: Plan 09-02 requires sync preview to read only public-intel tables and forbids candidate/proposal/sourced/tracker/fit/comp/note table reads.
- D-06: Plans 09-01, 09-02, and 09-06 require fail-closed scrub validation and local errors on forbidden private fields.
- D-07: Plan 09-02 adds one default-on onboarding sync-home toggle framed as helping improve CareerRat through public company and board metadata.
- D-08: Plan 09-02 requires consent copy saying resume, profile, notes, compensation, fit scores, jobs, tracker state, and local files are never shared.
- D-09: Plan 09-03 requires best-effort scraping for reachable public custom careers pages instead of stopping at unsupported ATS.
- D-10: Plans 09-02, 09-03, and 09-06 allow extraction to support local discovery and reduce AI calls while sync publishes metadata/confidence only, not job postings.
- D-11: Plans 09-03 and 09-05 keep unsupported/custom pages separate from supported ATS promotion and block `sourced-scan` writes until provider validation passes.
- D-12: Plans 09-03 and 09-04 enforce cascade order: supported ATS APIs, deterministic public-page extraction, scraper/API fallback, then bounded AI.
- D-13: Plan 09-05 restricts review to ambiguous/conflicting results: provider changes, multiple plausible boards, prior-data scrape blocks, robots-disallowed prior data, and low confidence.
- D-14: Plans 09-03 and 09-05 require clean no-result scans to record metadata and move on silently.
- D-15: Plan 09-04 requires bounded AI only for ambiguous usable page text and forbids AI on empty, blocked, robots-disallowed, or clearly useless pages.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Local scanner -> public tables | Mixed resolver/scanner objects are normalized into publishable metadata. |
| Onboarding UI -> sync preference | User consent controls whether public metadata can be prepared for sync-home. |
| Public page -> deterministic/AI extraction | Untrusted public HTML/text can influence metadata and review items. |
| Public metadata -> source config | Public metadata must not become private source config unless supported ATS validation approves it. |
