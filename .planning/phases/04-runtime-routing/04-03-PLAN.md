## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to proposal routes | User-entered company names cross into local proposal APIs. |
| local proposal route to chat runtime | Local errors must not escalate into chat or retained full-skill sessions. |
| runtime capability payload to UI | Chat handoff visibility depends on runtime-owned capability state. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-08 | Elevation of Privilege | CompaniesStep local proposal errors | high | mitigate | Tests assert local proposal failures render errors and do not start ChatPanel or POST /api/skill/run. |
| T-04-09 | Tampering | Proposal create payload | medium | mitigate | Send manual seeds only through Phase 3 POST route; do not persist source config or sourced rows from React. |
| T-04-10 | Information Disclosure | CompaniesStep payloads | medium | mitigate | Proposal UI sends company shortlist names/domain hints only; no private current-compensation fields are read from state or added to payloads. |
| T-04-11 | Repudiation | Runtime path selection | low | mitigate | Local proposal control and agent-led handoff are rendered as separate user actions. |
</threat_model>
