<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to decision route | User decision payload crosses to API and may cause confirmed source/sourced writes only on approval. |
| UI state to expected-version contract | Stale proposal state can otherwise mutate the wrong pending proposal. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-12 | Tampering | Proposal decisions | high | mitigate | Always send `expectedVersion` from the proposal card and handle 409 conflict by reloading proposal state. |
| T-04-13 | Elevation of Privilege | Approval actions | high | mitigate | Enable approve only for `proposedAction: approve-supported-ats`; let API enforce all final writes. |
| T-04-14 | Repudiation | Decision UI | medium | mitigate | Render returned decision metadata and refresh/reject results after each action. |
| T-04-15 | Information Disclosure | Error/manual metadata | low | mitigate | Display server-provided manual/error metadata only; do not serialize private current-compensation fields from app state. |
</threat_model>
