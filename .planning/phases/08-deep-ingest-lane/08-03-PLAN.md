<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser -> source routes | User-controlled text/files/URLs/local paths enter backend parsing and storage. |
| Scanner -> network | Public URL and repo fetches can target unsafe networks or huge responses. |
| Scanner -> filesystem | Explicit local paths can expose private local content if not constrained and previewed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-08-01 | Tampering | Source text | high | mitigate | Store source as data, escape previews later, and do not execute or route source-contained instructions. |
| T-08-02 | Information Disclosure | URL fetcher | high | mitigate | Scheme/host/redirect validation rejects private/local targets; tests cover SSRF-style inputs. |
| T-08-03 | Information Disclosure | Local path scanner | high | mitigate | Require explicit local-path kind, normalize paths, record metadata, and produce gaps for unsupported reads. |
| T-08-04 | Denial of Service | Upload/repo scanner | high | mitigate | Enforce JSON/upload/text/repo/time caps with 413 or explicit gap outcomes. |
| T-08-05 | Tampering | Source classification | medium | mitigate | Target shape is explicit user input; cross-lane suggestions remain secondary proposals in Plan 08-04. |
| T-08-06 | Information Disclosure | Source artifacts | high | mitigate | Store raw bodies only in local workspace/DB source state and keep telemetry out of this slice. |
| T-08-SC | Tampering | npm installs | low | accept | No package install is needed; scanner uses Node built-ins and existing helpers. |
</threat_model>
