# Phase 08 - UI Design Contract

> Visual and interaction contract for Deep Ingest Lane. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - use existing bespoke React/CSS system |
| Preset | not applicable |
| Component library | local components only: `Button`, `IconButton`, `Card`, `InlineAlert`, `Toast`, form primitives, chips, page scaffold |
| Icon library | local inline SVG icons from `apps/web/src/components/icons.jsx` |
| Font | Geist Sans for UI, Geist Mono for source IDs, hashes, and compact metadata |

Source: `apps/web/src/styles/tokens.css`, `apps/web/src/styles/app.css`, `apps/web/src/components/*`, `apps/web/src/library/LibraryPage.jsx`, `apps/web/src/inbox/*`, and Phase 7 UI-SPEC. No `components.json`, Tailwind, Radix, or shadcn registry is present or needed for this phase.

### Component Inventory

| Surface | Required Component Pattern |
|---------|----------------------------|
| Deep ingest page | `PageScaffold wide` with dense operational layout; no hero, no marketing copy |
| Lane checklist | Full-width lane progress band or left rail using compact bordered rows/chips, not nested cards |
| Targeted add flow | Segmented control on desktop and `Select` fallback on narrow mobile for target shape selection |
| Drop/paste/link input | Existing `.dropzone`, `TextArea`, `TextField`, and `Button`; source preview appears after ingest starts |
| Review queue | One compact repeated review row/card per source or proposal; filters are pill buttons; no giant table |
| Source preview | Framed tool panel with source metadata, fetch/scan status, and scrollable preview; long URLs use `word-break: break-all` |
| Proposal editor | Sibling framed tool panel with editable fields, grounding badges, validation messages, and confirm/defer actions |
| Manual fallback | `InlineAlert` plus editable form; never a dead-end error card |
| Completion/gaps | Status badge plus one concise detail line; terminal actions use `Button`, `Toggle`, or checkbox controls |

Hard visual rules for this phase:
- Do not add a landing page, hero, marketing panel, chat transcript, or full AI interview UI.
- Do not use colored left borders or accent strips on cards.
- Do not put cards inside cards. Use cards only for repeated queue/proposal items or a genuinely framed tool.
- Do not make a dense table. Use rows, chips, filters, and drill-in review surfaces.
- Do not introduce new global tokens unless an existing token cannot express a required state.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline source metadata, validation badge separation |
| sm | 8px | Compact row gaps, chip rows, filter groups, form control groups |
| md | 16px | Default section, editor, queue, and source/proposal split spacing |
| lg | 24px | Page header separation, lane checklist vertical rhythm, review workspace padding |
| xl | 32px | Desktop page content padding and major workspace gutters |
| 2xl | 48px | Wide layout max padding via existing app-shell clamp |
| 3xl | 64px | Reserved for app-shell/page separation only |

Exceptions: Existing component internals in `app.css` may retain current CSS values. New icon-only controls must be 32px square on desktop, matching `.icon-btn`; any new mobile-only icon tap target must be at least 44px square. The source preview and proposal editor may use fixed min-heights of 320px desktop and 220px mobile to prevent layout jumps during scan/proposal loading.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--paper-bg)` / `#faf6ef` | App background, deep ingest page canvas |
| Secondary (30%) | `var(--paper-surface)` / `#fffaf2`; `var(--paper-band)` / `#f5f0e8` | Review rows, source/proposal panels, neutral chips, lane checklist rest state |
| Accent (10%) | `var(--m-secondary)` / `#e8553d` | Primary CTA, active target selector/filter, keyboard focus outline, drag-active dropzone border, current review lane |
| Destructive | `var(--danger)` / `#ba2f20`; `var(--m-error-container)` / `#ffe0d8` | Remove/discard actions and error alerts only |

Accent reserved for: `Ingest source`, active target shape, active queue filter, active lane, keyboard focus outlines, drag-active dropzone border, and the current review item. Do not use accent as decoration.

Semantic status colors:
- Completed/Confirmed/Ready: `var(--teal)` text on `var(--teal-light)` background.
- Scanning/Deferred/Manual gap/Needs source: `var(--mustard)` text on `var(--mustard-light)` background.
- Source link/preview affordances: `var(--sky)` text only.
- Role-signal grouping: `var(--plum)` text or light mixed chip background where a second non-status tone is useful.
- Error/validation failed/destructive: `var(--m-error)` text on `var(--m-error-container)` background.

Dark mode must inherit from `[data-theme="dark"]` tokens. Do not hardcode light-only status backgrounds in components.

Accent reserved for: primary ingest/confirm actions, active controls, focus/drag state, and current-lane emphasis only.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Ingest source |
| Review CTA | Review proposals |
| Confirm CTA | Confirm proposal |
| Save edits CTA | Save edits |
| Manual fallback CTA | Enter manually |
| Retry CTA | Retry ingest |
| Defer CTA | Defer lane |
| Not available CTA | Mark not available |
| Empty state heading | No deep ingest sources yet |
| Empty state body | Paste, drop, or link profile material to create reviewable proposals for evidence, stories, honesty, voice, and role signals. |
| Error state | Ingest could not finish. The source was saved; review the gap, retry, or enter details manually. |
| No AI state | AI extraction is unavailable. The source was saved; enter the proposal manually or defer this lane. |
| Source unreadable state | Source saved, but CareerRat could not read enough content. Add text manually, mark it not available, or defer it as a visible todo. |
| Completion state | Deep ingest lanes are terminal. Deferred items remain visible as todos. |
| Destructive confirmation | Remove source: Remove this source and its proposals from Deep ingest? This cannot be undone. |

Copy rules:
- Use "source", "proposal", "gap", "lane", and "terminal" consistently.
- Do not say "AI interview", "chat", "agent", "skill", or "automation" for Phase 8 deep ingest.
- For failed AI/provider/schema states, always state that the source was saved.
- For deferred and not-available states, name the affected lane in the visible row.
- Do not imply a source was successfully ingested when it was unreadable, login-gated, truncated, unsupported, or private.

## Interaction Contract

### Layout

- Use `PageScaffold wide` titled `Deep ingest`.
- Primary focal point is the intake cluster until proposals exist; then the active review item and proposal editor become the visual anchor.
- Desktop layout: top intake band, lane checklist below it, then a two-column workspace: review queue/source list at `260px-320px`, review detail at `minmax(0, 1fr)`.
- Review detail desktop split: source preview and proposal editor as sibling panels in a responsive grid, each `minmax(280px, 1fr)`.
- Mobile layout under 760px: stack intake, lane checklist, review queue, source preview, and proposal editor. Action rows wrap; primary/secondary text buttons become full-width when two or more actions share a row.
- Lane checklist stays visible near the top of the page after each action. Do not hide completion/gap state inside a drawer only.

### Target Shape Selection

Required target shapes:

| Target | Label |
|--------|-------|
| `auto` | Auto |
| `evidence` | Evidence |
| `story` | Story |
| `writing_voice` | Writing voice |
| `honesty_boundary` | Honesty |
| `role_signal` | Role signal |
| `paste` | Paste |
| `link` | Link |

- If launched from a type-specific evidence/story/voice/honesty/role-signal flow, default the target to that type and review as that type.
- If launched from Library or the generic Deep ingest page, require a visible target shape selection before `Ingest source` is enabled. `Auto` may be the default only for truly unknown or cross-cutting material.
- Use a segmented control for desktop when space allows; use the existing `Select` component below 520px or when labels wrap.
- Do not silently reclassify a user-selected target into another trusted shape. Cross-lane suggestions may appear as secondary proposal items with their own confirm buttons.

### Source Intake

- Accept pasted text, dropped files, public URLs, public repo links, portfolio links, recruiter/job context, and explicit local paths.
- Show one input cluster: target selector, text/link field, dropzone, and `Ingest source`.
- During scan/extraction, disable `Ingest source`, preserve the user's text/file/link on screen, and show `Scanning source...` followed by `Building proposals...` when bounded extraction starts.
- Every submitted source must resolve to one visible row: proposal ready, manual fallback, gap, deferred, not available, or failed. Nothing disappears after submit.
- Existing global `CaptureBar` remains generic. Phase 8 may route generic captures into the review queue, but type-specific Deep ingest actions should use the target-shaped intake surface above.

### Lane Checklist

Required lanes:

| Lane | Required UI |
|------|-------------|
| Source coverage | Count captured sources, unreadable sources, and sources with open gaps |
| Evidence claims | Count proposals, confirmed claims, and blocked/low-confidence claims |
| Story bank | Count draft stories, confirmed stories, and missing STAR/R detail |
| Honesty boundaries | Count confirmed do-not-claim/allowed-wording boundaries and conflicts |
| Writing voice | Show `Missing`, `Review`, or `Ready`; do not use a numeric score as the only signal |
| Role signals | Count keep/cut/role-family signal proposals and confirmed signals |
| Open gaps | Count visible deferred todos, manual gaps, and not-available states |

Lane statuses:

| State | Label | Terminal |
|-------|-------|----------|
| `not_started` | Not started | no |
| `needs_source` | Needs source | no |
| `scanning` | Scanning | no |
| `review_needed` | Review | no |
| `gap` | Gap | no |
| `completed` | Complete | yes |
| `deferred` | Deferred | yes |
| `not_available` | Not available | yes |
| `failed` | Failed | no |

- `deep_ingest_complete` may show ready only when every required lane is terminal: `completed`, `deferred`, or `not_available`.
- A deferred lane must remain visible as a todo with a one-line reason.
- A not-available lane must require a checkbox/toggle plus a reason field before it becomes terminal.

### Review Queue

- Queue filters: `All`, `Review`, `Gaps`, `Deferred`, `Confirmed`, `Failed`.
- Each row shows target shape, source label, status badge, one-line proposed action/gap, source kind, and updated time.
- Rows use status badges/icons/text; never a colored left border.
- Row actions: `Review proposal`, `Retry ingest`, `Defer lane`, `Mark not available`; show only actions valid for the row status.
- The queue empty state changes by filter. For the main empty state use the copy in the Copywriting Contract. For filtered no-results use: `No items match this filter.`

### Source Preview

- Always show source label, kind, target, scan status, fetch status, source artifact ID/path, and chunk count when present.
- Preview text must preserve line breaks, cap height with internal scroll, and use `overflow-wrap: anywhere` for long strings.
- For URLs/repos, show fetched/read status as badges: `Fetched`, `Public`, `Login gated`, `Too large`, `Truncated`, `Unsupported`, `Failed`.
- Login-gated, private, huge, unsupported, truncated, and unreadable sources must create an explicit gap row. Do not mark the source as complete solely because it was saved.
- Source text is untrusted data. Do not render source-provided HTML as HTML; render as escaped text or sanitized plain preview.

### Proposal Editor

- Proposal editor must be editable before confirmation.
- Every proposed item shows source reference, confidence, validation state, and supporting quote/span where available.
- Validation badges: `Grounded`, `Needs quote`, `Conflict`, `Private`, `Low confidence`, `Schema failed`.
- Confirming a proposal writes trusted candidate state only through an explicit `Confirm proposal` or `Confirm selected` action.
- Editing a claim/story/signal that affects the supporting quote or source reference must move the item back to `Needs quote` until the user supplies support or confirms it as a manual note/gap.
- Destructive removal is not the normal path. Prefer `Defer lane`, `Mark not available`, or `Reject proposal`; hard deletion uses the destructive confirmation copy above.

Required editor fields by target:

| Target | Fields |
|--------|--------|
| Evidence | Claim, supporting quote, source reference, confidence, tags, allowed wording |
| Story | Title, situation, task/problem, action, result, reflection, evidence links, missing detail |
| Writing voice | Voice summary, do phrases, avoid phrases, source sample references |
| Honesty | Boundary type, allowed wording, forbidden wording, reason, source reference |
| Role signal | Signal type keep/cut/risk, role family, rationale, source reference |
| Paste/link | Label, source kind, summary, next target, gap reason |

### AI and Manual Fallback States

| Condition | Required UI |
|-----------|-------------|
| `NO_AI_ROUTE` | Warning alert, `Enter manually`, `Defer lane`; source remains saved |
| `AI_SCHEMA_INVALID` | Error alert, validation details summarized without raw model text, `Retry ingest`, `Enter manually` |
| `AI_PROVIDER_FAILED` | Error alert, `Retry ingest`, `Enter manually`; do not discard source |
| Grounding failure | Item-level `Needs quote` or `Conflict` badge; block direct confirmation for that item |
| Sensitive/private data flag | Item-level `Private` badge; block outbound/reusable confirmation until user edits or marks private |
| Source unreadable/truncated/login-gated | Gap row with source status badge; `Enter manually`, `Defer lane`, `Mark not available` |

Manual fallback is a first-class state, not an error-only endpoint. The user must be able to finish the lane by entering a manual proposal, deferring it, or marking it not available.

### Completion and Readiness

- Show progress as terminal lane count, e.g. `4 of 7 lanes terminal`, not a vague percentage.
- `Deep ingest complete` appears only when all required lanes are terminal.
- If sourcing is running from Phase 7, keep its state separate. Deep ingest progress must not block or mask the sourcing run.
- The Home setup readiness chip for `Deep ingest` should summarize the same terminal-state model: `Ready`, `Needs review`, `Deferred`, or `Needs source`.

### Accessibility and Responsiveness

- Target selector uses radio/segmented semantics with `aria-pressed` or an actual `select` fallback.
- File/drop controls must be keyboard-operable buttons with hidden file inputs, following `ResumeStep`.
- Icon-only controls must use `IconButton` with `aria-label` and `title`.
- Review/proposal status changes use `aria-live="polite"` on the queue count/status line.
- Focus states use the existing 2px `var(--m-secondary)` outline.
- Text in buttons, chips, rows, and lane tiles must wrap or truncate deliberately; no horizontal overflow below 360px.
