</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser file upload -> local route | Untrusted DOCX bytes and filename enter local storage. |
| Mammoth parser -> extracted text | Parser output is untrusted text that can influence candidate readiness. |
| React onboarding -> form defaults DB | User document-format preferences update local packet-generation defaults. |
| npm registry -> local runtime | New runtime dependency is installed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Tampering | DOCX upload filename | high | mitigate | Use `sanitizeUploadFilename` and fixed `workspace/intake/resume-uploads/` storage. |
| T-07-02 | Denial of Service | DOCX parser input | high | mitigate | Use `readRawBodyCapped` with DOCX-specific cap before Mammoth extraction. |
| T-07-03 | Information Disclosure | DOCX parser options | medium | mitigate | Use `mammoth.extractRawText({ buffer })`; do not enable external file access or HTML conversion. |
| T-07-04 | Tampering | `source-resume` artifact | high | mitigate | Write `source-resume` only after `looksLikeUsableResumeText()` passes. |
| T-07-05 | Tampering | Packet export format defaults | medium | mitigate | Schema restricts formats to `pdf`/`docx`, defaults to PDF, and tests reject unknown formats. |
| T-07-SC | Tampering | npm install `mammoth` | high | mitigate | Package legitimacy audit in `07-RESEARCH.md` marks `mammoth` OK; install exactly `mammoth@1.12.0` and do not add unaudited packages. |
</threat_model>
