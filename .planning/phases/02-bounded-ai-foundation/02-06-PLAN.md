## Phase Goal

**As a** CareerRat app surface, **I want to** call cheap bounded AI primitives, **so that** users receive consistent success, manual, and error envelopes without launching full skills.

<objective>
Migrate the resume-AI upload route to the shared envelope while preserving its read-only skill-runtime adapter.

Purpose: Current `resume-ai` schema failures return raw model text. Phase 02 decisions require shared envelopes and no raw prompt/output leakage. This plan fixes that route without changing the file-reading runtime it needs.
Output: Resume-AI returns shared envelopes and the web API wrapper unwraps successful data for the existing onboarding UI.
</objective>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| browser upload -> onboard route | PDF/image bytes enter the local server. |
| onboard route -> read-only skill runtime | Saved local file path is passed to the resume-extract skill with `Read` only. |
| model output -> onboard route | Resume extraction JSON returns from untrusted model output. |
| onboard route -> browser | Seed data and manual fallback envelopes return to the onboarding UI. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-02-06-01 | Information Disclosure | resume-AI 422 response | high | mitigate | Remove raw assistant text from schema failure responses and test serialized body. |
| T-02-06-02 | Tampering | resume extraction output | high | mitigate | Validate against `config/resume-extract.schema.json` through `runBoundedAI()` before success. |
| T-02-06-03 | Elevation of Privilege | skill tool surface | high | mitigate | Preserve explicit `tools:["Read"]` for resume-extract invocation. |
| T-02-06-04 | Denial of Service | upload body | medium | mitigate | Preserve 5MB raw body cap and extension validation. |

</threat_model>
