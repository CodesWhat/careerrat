## Phase Goal

**As a** CareerRat app surface, **I want to** call cheap bounded AI primitives, **so that** users receive consistent success, manual, and error envelopes without launching full skills.

<objective>
Add provider-native structured-output request support to the existing `callAI()` boundary.

Purpose: D-13 adopts native structured outputs, but D-16 keeps provider-specific request bodies hidden below CareerRat APIs. This plan extends `callAI()` so later helper and route plans can request native structured output without hard-coding Anthropic request shape in route modules.
Output: `callAI()` accepts structured output options and tests prove BYOK/proxy request shape and labels with mock upstreams.
</objective>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| helper/route -> `callAI()` | Local code asks provider for native structured output. |
| `callAI()` -> BYOK/proxy upstream | Provider-specific request body leaves the local process. |
| `callAI()` -> usage log | BYOK path writes metadata-only usage rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-02-02-01 | Tampering | native output request shape | medium | mitigate | Tests assert the schema is placed under `output_config.format` only when explicitly requested. |
| T-02-02-02 | Repudiation | proxy label headers | high | mitigate | Proxy native tests assert `x-careerrat-skill` and `x-careerrat-action` are preserved. |
| T-02-02-03 | Information Disclosure | BYOK usage rows | high | mitigate | Preserve `usageRow()` metadata-only fields; do not add request content or schema payload to usage events. |
| T-02-02-04 | Denial of Service | streaming path | low | accept | Native structured output is non-streaming for bounded routes; existing streaming tests remain unchanged. |

</threat_model>
