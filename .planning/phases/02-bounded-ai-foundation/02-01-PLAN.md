## Phase Goal

**As a** CareerRat app surface, **I want to** call cheap bounded AI primitives, **so that** users receive consistent success, manual, and error envelopes without launching full skills.

<objective>
Create the shared bounded AI helper contract that later route plans consume.

Purpose: Phase 02 needs one reusable invocation and envelope contract, not route-local AI handling. This plan implements D-01 through D-12 at the helper boundary while keeping native provider request support for the next plan.
Output: A tested helper module under `src/core/ai/` and a new hermetic node:test suite.
</objective>

<threat_model>

## Trust Boundaries

| Boundary | Description |
| --- | --- |
| route -> bounded helper | Route input and prompts cross into the shared AI contract. |
| bounded helper -> model/provider | Untrusted model output returns from BYOK/proxy/provider. |
| bounded helper -> app surface | Route envelopes become renderable app data. |
| bounded helper -> telemetry | Usage metadata may be written through BYOK/proxy paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-02-01-01 | Repudiation | `requireBoundedAILabels` | high | mitigate | Reject missing or blank `skill`, `action`, and `operation` before invocation; test invocation spy remains uncalled. |
| T-02-01-02 | Tampering | `runBoundedAI` schema path | high | mitigate | Use `runStructuredOneshot()` and local schema validation before exposing `body.data`. |
| T-02-01-03 | Information Disclosure | `makeBoundedAIEnvelope` | high | mitigate | Envelope excludes raw prompt, raw model text, resumes, JDs, candidate facts, and page bodies; tests inspect serialized body. |
| T-02-01-04 | Denial of Service | retry loop | medium | mitigate | Bound retries with `maxRetries` and return stable manual envelopes instead of unbounded retry or route crash. |
| T-02-01-05 | Spoofing | provider metadata | low | accept | `ai.model` is explanatory metadata only and is not used for writes or authorization in this phase. |

</threat_model>
