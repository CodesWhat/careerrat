<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Client -> gate route | User-controlled application IDs and options enter the local packet gate API. |
| Client/JD body -> local artifact store | User- or provider-supplied JD/body text is persisted under `workspace/jobs/` and stamped onto the DB application row. |
| JD/application context -> bounded AI | Untrusted job text and company context become model input for finite judgment. |
| AI verdict -> local gate result | Schema-validated model output influences review/KEEP/CUT state but not artifacts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-10-02-01 | Tampering | `evaluatePacketGate()` | high | mitigate | Use `packetGateAiVerdictSchema`, deterministic validation, and manual/review fallback before exposing gate output. |
| T-10-02-02 | Information Disclosure | Gate prompt/response | high | mitigate | `buildPacketContext()` excludes current compensation/private fields; tests scan envelopes for raw prompt/model/context leakage. |
| T-10-02-03 | Denial of Service | `POST /api/packet/gate` | medium | mitigate | Reuse capped JSON body reader and return local 400/413-style failures. |
| T-10-02-04 | Repudiation | Gate decision metadata | medium | mitigate | Include reasons, ai/manual metadata, and source timestamps in route response for later manifest stamping. |
| T-10-02-05 | Tampering | `capturePacketJobBody()` | high | mitigate | Persist supplied JD/body text before gate judgment, stamp `artifacts.jd` through a DB verb, reject empty/unreadable bodies with manual review, and never treat links alone as captured content per D-02. |
| T-10-SC | Tampering | npm installs | low | accept | No package installs. |
</threat_model>
